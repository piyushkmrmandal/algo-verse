4. Starting Infrastructure with Docker

✅ Recommended: Start all infra with one command
make infra
# or
docker compose -f docker-compose.infra.yml up -d

To start each infrastructure component individually (e.g. if you want fine-grained control), use the commands below. All commands create a shared algoverse-net bridge network so services can resolve each other by container name.

# Create the shared network once
docker network create algoverse-net 2>/dev/null || true

4.1 PostgreSQL 16

PostgreSQL :5432 Infrastructure
Primary relational database. Each microservice gets its own logical database, all on this single Postgres instance. The init.sql script creates all 10 databases on first boot.
docker run -d \
  --name algoverse-postgres \
  --network algoverse-net \
  -p 5432:5432 \
  -e POSTGRES_USER=algoverse \
  -e POSTGRES_PASSWORD=secret \
  -e POSTGRES_DB=algoverse \
  -v algoverse_postgres_data:/var/lib/postgresql/data \
  -v $(pwd)/docker/postgres/init.sql:/docker-entrypoint-initdb.d/init.sql:ro \
  --health-cmd="pg_isready -U algoverse" \
  --health-interval=10s \
  --health-retries=5 \
  postgres:16-alpine

Databases created by init.sql:

auth_db  ·  problem_db  ·  submission_db  ·  gamification_db  ·  ai_db  ·  analytics_db  ·  sysdesign_db  ·  execution_db  ·  collaboration_db  ·  notification_db

Connect with psql

docker exec -it algoverse-postgres psql -U algoverse -d auth_db

Connect with a GUI (TablePlus / DBeaver)

  • Host: localhost · Port: 5432
  • User: algoverse · Password: secret
  • Select the database you want to inspect

4.3 Apache Kafka + Zookeeper

Zookeeper + Kafka :2181 / :9092 / :29092 Infrastructure
Event backbone. Services communicate asynchronously via 13 topics (submission results, badge events, XP awards, notifications, etc.). Port 29092 is the host-accessible listener; services inside Docker use kafka:9092.
# Step 1 — Zookeeper (must be healthy before Kafka starts)
docker run -d \
  --name algoverse-zookeeper \
  --network algoverse-net \
  -p 2181:2181 \
  -e ZOOKEEPER_CLIENT_PORT=2181 \
  -e ZOOKEEPER_TICK_TIME=2000 \
  confluentinc/cp-zookeeper:7.6.0

# Wait ~10 seconds, then start Kafka

# Step 2 — Kafka broker
docker run -d \
  --name algoverse-kafka \
  --network algoverse-net \
  -p 9092:9092 \
  -p 29092:29092 \
  -e KAFKA_BROKER_ID=1 \
  -e KAFKA_ZOOKEEPER_CONNECT=algoverse-zookeeper:2181 \
  -e KAFKA_LISTENER_SECURITY_PROTOCOL_MAP=PLAINTEXT:PLAINTEXT,PLAINTEXT_HOST:PLAINTEXT \
  -e KAFKA_ADVERTISED_LISTENERS=PLAINTEXT://algoverse-kafka:9092,PLAINTEXT_HOST://localhost:29092 \
  -e KAFKA_INTER_BROKER_LISTENER_NAME=PLAINTEXT \
  -e KAFKA_OFFSETS_TOPIC_REPLICATION_FACTOR=1 \
  -e KAFKA_AUTO_CREATE_TOPICS_ENABLE=false \
  confluentinc/cp-kafka:7.6.0
ℹ️ Kafka UI (optional)
docker run -d \
  --name algoverse-kafka-ui \
  --network algoverse-net \
  -p 8089:8080 \
  -e KAFKA_CLUSTERS_0_NAME=local \
  -e KAFKA_CLUSTERS_0_BOOTSTRAPSERVERS=algoverse-kafka:9092 \
  provectuslabs/kafka-ui:latest
Then open http://localhost:8089

4.4 Elasticsearch 8

Elasticsearch :9200 Infrastructure
Full-text problem search. Used exclusively by problem-service, which auto-indexes all problems on startup via a @EventListener(ApplicationReadyEvent.class) hook.
docker run -d \

  --health-cmd="curl -sf http://localhost:9200/_cluster/health || exit 1" \
  --health-interval=15s \

5. Database Initialisation

The docker/postgres/init.sql file runs automatically on the first container start. It creates all 10 databases and grants privileges to the algoverse user.

Each Spring Boot service uses Flyway to manage its own schema. Migrations live at src/main/resources/db/migration/ and run automatically on service startup. No manual DDL execution is needed.

⚠️ First-start order matters
PostgreSQL must be healthy before any Spring Boot service starts, otherwise Flyway will fail to connect and the service will crash-loop. Always use depends_on: condition: service_healthy in docker-compose (already configured).

7. Starting Each Service

Every service can be started in two ways: (A) locally with Maven/uvicorn (for active development — fast restart, IDE debug), or (B) via Docker. Both approaches are shown for each service.

ℹ️ Java services — JAVA_HOME
Always export JAVA_HOME pointing to JDK 21 before running Maven commands: 
# macOS (Homebrew Temurin 21)
export JAVA_HOME=$(/usr/libexec/java_home -v 21)
# Linux
export JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64

7.1 auth-service Java 21

auth-service :8081
JWT RS256 authentication, refresh token rotation, OAuth2 (Google / GitHub / LinkedIn), user registration & login. All other services depend on the public key it issues.

cd services/auth-service

  -p 8081:8081 \

7.9 ai-service Python 3.12

ai-service :8090
FastAPI service powered by Ollama (open-source local LLM — no API key required). Provides streaming AI hints, code review, Bayesian Knowledge Tracing (BKT) personalization, and system design feedback. All LLM calls go through the Ollama REST API at http://localhost:11434 via plain httpx.
PostgreSQL → ai_db Redis Kafka Ollama running locally
ℹ️ Ollama one-time setup (macOS)
# Install Ollama
brew install ollama

# Pull the default model (≈4 GB download, one-time)
ollama pull qwen2.5-coder:7b

# Start the Ollama server (keep running in a terminal)
ollama serve
Ollama listens on http://localhost:11434 by default. Any model available at ollama.com/library works — change AI_MODEL env var to switch.

13. Troubleshooting

Service fails with "Connection refused" to PostgreSQL

Cause: Service started before Postgres was healthy.
Fix: docker compose restart <service-name> — the depends_on: condition: service_healthy is only enforced on first start, not restart.

Kafka consumer never receives messages

Cause: Topics not created yet, or consumer group offset is ahead.
Fix: 
make kafka-topics   # create missing topics
# Reset offsets if needed:
docker exec algoverse-kafka kafka-consumer-groups \
  --bootstrap-server localhost:9092 \
  --group notification-service --reset-offsets --to-earliest \
  --topic algoverse.badge.earned --execute

Flyway migration failure on startup

Cause: Database schema is out of sync (e.g. after make clean + make up with schema changes).
Fix: make clean wipes volumes — re-running make up will re-run all Flyway migrations from scratch.

Out of memory / containers OOM-killed

Cause: Docker Desktop memory limit too low.
Fix: Increase Docker Desktop memory to at least 10 GB (Settings → Resources → Memory).
Alternatively, use make infra and run only the services you need locally.

execution-service cannot spawn containers

Cause: Docker socket not mounted or permission denied.
Fix: Ensure the container has -v /var/run/docker.sock:/var/run/docker.sock. On Linux, add the container user to the docker group.

ai-service returns 503 or hints don't stream

Cause: Ollama is not running or the model hasn't been pulled.
Fix: 
# 1. Start Ollama
ollama serve

# 2. Pull the model (one-time, ~4 GB)
ollama pull qwen2.5-coder:7b

# 3. Verify Ollama responds
curl http://localhost:11434/api/tags
# Should list qwen2.5-coder:7b in the models array
No API key or cloud account is required — everything runs locally.

Frontend cannot connect to backend (CORS errors)

Cause: VITE_API_BASE_URL pointing at wrong address, or CORS not configured.
Fix: Set VITE_API_BASE_URL=http://localhost:80 in apps/web/.env.local. Each Spring Boot service already has @CrossOrigin for localhost:5173.

Port already in use

Fix: 
# Find what's using port 8081
lsof -i :8081        # macOS/Linux
netstat -ano | findstr :8081  # Windows

# Kill the process
kill -9 <PID>
